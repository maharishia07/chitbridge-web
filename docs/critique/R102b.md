# Critique · R102b (written before any code, 2026-10-24) — Pay has no confirm

## (a) What the brief assumes, checked
- "the Pay button lives in cap-finance-pay.js" — PARTLY. `fpPay` (cap-finance-pay.js:72) only OPENS the sheet; the ONE write is `payRecord` (cap-books.js:1507, POST /api/books/payments) behind the sheet's Record button, reached from CB Finance (fpPay), CB CRM (crm-act-pay, rpay), CB Accounts Dues, Bank rec (bankRecord) and app.html Customers › Receive. One place to ask: payRecord.
- "follow R102's CBAction.ask" — TRUE on every utility page (crm/accounts/finance/tasks alias `confirmAsk = CBConfirm`, a stacked `<dialog>`); FALSE on app.html: `confirmAsk` there paints into `#modalhost` (app.html:9787 → modal()), the SAME host the pay sheet occupies, so CBAction.ask would replace the form before the write and `payOutcomePaint` would have no `pay_body`. The ask goes through `CBConfirm` directly (accounts-shell.js:721, loaded by all five pages) — the same dialog R102 ends up in on accounts.html.
- "the screen knows the mode" — TRUE: `#pay_mode` (cash · UPI/pack modes · bank · card · cheque), read by `payMode()`.
- "Record payment on the customer side" — TRUE: the same sheet (`kind === 'customer'`, title "Receive · name", button Record).

## (b) Conflicts with rules and constructs
- The band ("Nothing is owed to X … Pay ₹3,720.12 again as an advance?" → "Pay as advance", cap-books.js:1440) already IS a deliberate confirm naming who and how much; asking a second time there would be a double ask that trains click-through. One ask per write: band path = the band, plain path = the dialog.
- `CBAction.ask` would be the one door; widening it (`stack: true` → CBConfirm) is accounts-shell.js, CARD 29 (G-DESIGN/QUALITY), not finance — not touched; named in the report as the follow-up that makes `payAsk` collapse into `CBAction.ask`.
- Undo stays out (brief). No api change, no engines, no migration.

## (c) A simpler way
- None simpler than one `payAsk()` in front of the existing `CBAction.run` in payRecord; the write itself moves unchanged into `payWrite()` (payRecord shrinks).
