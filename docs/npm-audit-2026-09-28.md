# npm audit — chitbridge-web, 2026-09-28

**Asked for by backlog M26** ("remove unused `tailwindcss` + `npm audit`). **Tailwind was NOT removed: it is not unused.**
The root `index.html` loads the frozen React SPA (`src/main.jsx`); `src/index.css` opens with `@tailwind` directives and
`postcss.config.js` requires the `tailwindcss` plugin. `src/FROZEN.md`: *"The SPA at `/` (and its routes `/simulator`,
`/tour`, `/network`, `/catalogue`) still deploys from `src/`."* Removing Tailwind would break the Vite build of the live
root. Whoever wrote "unused" looked at `public/`, which never uses it.

## Findings (8: 4 high, 4 moderate, 0 critical)

| Package | Severity | Direct? | What | Reaches users? |
|---|---|---|---|---|
| `vite` | high | direct | path traversal in optimised deps `.map` handling | dev server / build only |
| `postcss` | high | direct | `sourceMappingURL` can read arbitrary `.map` files when `from` is unset | build only |
| `browserslist` | high | via build | unbounded memory growth | build only |
| `nanoid` | high | via build | non-secure generator can loop on a negative size | build only |
| `esbuild` | moderate | via vite | any site can send requests to the **dev** server | dev server only |
| `baseline-browser-mapping` | moderate | via build | process termination on invalid input | build only |
| `react-router` / `react-router-dom` | moderate | direct | open redirect via a backslash in `<Link>` / `useNavigate` | **yes — the frozen SPA at `/`** |

## What it needs (a decision, not a night fix)

Every fix is a dependency upgrade in the build that deploys the live root, which is out of scope for an unattended
change. Two ways out:
1. **Upgrade** `vite`, `postcss`, `react-router-dom` (and let the transitive ones follow), then check the SPA still builds
   and its routes still render.
2. **Retire the frozen SPA** at `/`: point `/` at `app.html` (or a landing page) and drop `src/` from the build. That also
   removes Tailwind, PostCSS and the React build chain, and with them every finding above. `FROZEN.md` says `src/` is
   kept for *mining*, not for serving; the concepts it names (`/simulator`, `/tour`, `/network`, `/catalogue`) would need
   checking against `app.html` first.

Recommendation: option 2, once the four routes are confirmed carried into `app.html`. It shrinks the attack surface and
the build, rather than keeping a frozen app patched.
