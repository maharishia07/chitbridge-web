# CRM2 critique — the chit page inside CB CRM (`crm.html#/chit/<id>`), written before any code (2026-10-13)

**(a) What the brief assumes, checked**
- "crm.html exists and the chits live in CB CRM › Chits" — TRUE: `crm.html:299` (nav Chits), `cap-crm-chits.js:92` (a row opens the sheet in place).
- "`paintDetail` is a screen that can be extracted to `app/cap-*.js` and loaded in both pages" — FALSE in practice: `paintDetail` (`app.html:16397`) → `detailInner` (`app.html:16769-16880`) reads the workshop's state (`UI.rows · UI.folder · UI.dtab · SESSION.role · DACT/dactShows`) and calls ~40 app.html-only painters and actions (`contentItems · viaBlock · frozenMoneyHTML · statusTabHtml · messagesTab · booksBlockHTML · chitSpendStrip · cancelBanner · forwardChit · moveChit · pickChitStatus · pickAssign · withdrawChit · askAiOrder …`); `openChit` (`app.html:16286`) fills it from `UI.rows` through `mapApiChit · fmtLine · mapAtt`. It is the Task workshop's right pane, not a module.
- "the full page is M53" — M53 is a REQUIREMENT, not a build (`docs/design/chit-detail/REQUIREMENT.md`: "requirement only. Not designed, not built"); its own table says design 1 (this pane) RECOMPUTES the money (`CBCart.moneyFromLines`) and is to be REPLACED by one module "every page opens, in a popup, side pane or full page", whose one reader is `chit-sheet.js moneyFor`.
- "`pages.json` base script → crm.html" — the `script` field is read by nothing at runtime (`page.js` only returns it; `e2e/detail-page.cjs:51` checks the file exists); `chitbridge-api/data/pages.json` is a byte copy (`tests/page-name.test.cjs`) → a twin PR.
- `CB_HOMES` (`accounts-shell.js:26`) has no `chit` key — TRUE; the three `openChitPage` are the only doors (`accounts.html:432 · crm.html:379 · finance.html:368`).

**(b) Rule conflicts** — moving `paintDetail` would carry a SECOND money computation into a customer page (one calculation; M53 row 1) and a dozen app.html globals with it (one place per thing). The sheet already is the one reader of the frozen figures, carries the rail units (CBThread · CBAttach, R10) and paints only the actions the step allows (`actionsFor`), the server's `chit.actions` deciding who may post.

**(c) Simpler way** — WIDEN `chit-sheet.js` with a page host: `CBSheet.mount(el, id)` paints with the SAME painters (header · lines · GST · total · tender · rail) into the CRM work pane instead of the `<dialog>`; the page form drops the `page` icon (you are on it) and adds what the popup leaves out: the chit's history (`state_log`, read, never worked out) and the CBPage note (`page.js`). `crmRoute` gets `chit/<id>`; the three `openChitPage` → `/crm.html#/chit/<id>`; `CB_HOMES.chit` names it.

**(d) Risks** — (1) app.html's design 1 is NOT deleted: the workshop keeps its pane until M53 is designed; the customer's chit page is the sheet's page form (one module, two hosts). (2) `e2e/chit-sheet.cjs` pins the popup's icon rows and "Open page" — the page form must leave the popup form byte-for-byte in behaviour. (3) Twin landing: IX0 (#166, the guard and the doc) first; then web and api (`data/pages.json` byte copy) in either order — CI's twin check pairs the branch names. (4) `crm.html` is also touched by open rounds (WX-L2C #165, CS2 #169): the change here is one script tag and one route line, so a merge is small. (5) No money, no new route, no SQL.

**(e) VERDICT: BUILD WITH CHANGES** — (i) the chit page is the chit sheet mounted full-page in CB CRM (widened, never a second painter); `paintDetail` stays in the workshop and is not extracted — it recomputes money and is workshop state, and M53 says it is the thing to be replaced; (ii) `pages.json` base script → `crm.html` with the api byte copy in a twin PR; (iii) the walk is `e2e/walk-chit-page.cjs`: light + dark at 1366 and 390 px with `e2e/lib/theme-measure.cjs`, no clipping, no app.html link, the text budget.
