# WX-P2P · procure to pay, walked on a real stack — findings (13 Oct 2026)

The walk: `e2e/walk-x-p2p.cjs --real` (`--only W` the width half, `--only D` the depth half). Shots in `e2e/shots/wxp2p-*.png` and
`e2e/shots/walk-x-p2p-NN.png`. The flow is docs/process/P2P.md (steps 1–6). Standards: docs/design/SYSTEM.md + standards/.

## The stack (what the runner did; the dev PC's local-stack.sh is the same three doors)

```
docker run -d --name cbpg -p 5432:5432 -e POSTGRES_PASSWORD=pw postgres:16
PGPASSWORD=pw psql -h 127.0.0.1 -U postgres -c "create database cb_local"
cd ../chitbridge-api && npm ci
node tools/sim-load.cjs --db postgres://postgres:pw@127.0.0.1:5432/cb_local --schema --shop simstores        # the buyer, 3 years (≈ 2½ min)
node tools/sim-load.cjs --db postgres://postgres:pw@127.0.0.1:5432/cb_local --shop kumartrade --seed 11 --years 1   # the supplier shop (≈ 1 min)
cd ../chitbridge-web && node e2e/lib/stack-local.cjs up        # api on 3000 · public/ on 5173 · DEV_OTP 123456
cd e2e && npm ci && npx playwright install --with-deps chromium && cd ..
NODE_PATH=$PWD/e2e/node_modules node e2e/walk-x-p2p.cjs --real
```

The walk itself makes the rest, idempotently, through the api's doors: the supplier shop is renamed **Kumar Trade Co** with a public
catalogue, listed by `simstores` as a resale supplier and listing it as a customer (`ensureSupplier`); the DEPTH half buys as a fresh
shop **walkbuyer** (Walk Buyer Stores: IN · INR · FY April · a Tamil Nadu GSTIN · ledger on · opening cash ₹2,00,000) with a view-only
co-assist **vani@walkbuyer** (`ensureBuyer`) — because the loader locks every month it wrote, the present one included (WX-P2P-08).

## Screens and operations walked

Width (1366 × 768 and 390 × 844, every control, no sideways scroll): Supplies · Intake · Suppliers · Task · Order · CB Accounts To do ·
Payables · Unpaid bills · Day book · Ledgers · Trial balance · P&L · Waiting · Cheques · GST close & pay; the Pay sheet, the Add-a-supply
sheet and the supplier's catalogue at 390 (18 paths).

Depth (24 paths, two parties + a view-only login): sign in → Supplies add · record a purchase (cash, off-rail) · used some · refused without a
reference → Intake empty state → Suppliers › Kumar Trade Co › Items · Details · Review · Send order → the supplier's Task sees it, sets Act
→ the supplier bills the buyer (its counter bill on credit, the loader's shape) → Unpaid bills › Received → the sheet (Accept · Dispute ·
Goods in · Open page) → Open page › ⧉ Lines › Delivered 2 of 2 → Goods in › For resale → Accepted → Payables · Day book PV (Purchases +
GST) · Ledgers › Suppliers › the party → Pay (oldest first, Record, the advice sent, the supplier's Task holds the advice) → Payables /
Unpaid bills after → TB · P&L · GST close → Reverse the payment with a reason (the trail shows both) → the view-only login on Pay and GST close.
